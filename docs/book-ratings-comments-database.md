# Book ratings and comments: Prisma database integration

Owner: Rene Rodriguez. Runtime: Node.js 24, Express 5, Prisma 6.19.3.

## API contract

| Method and path | Input | Success |
| --- | --- | --- |
| POST /books/:bookId/ratings | Profile Basic authentication and JSON with userId and an integer rating from 1 through 5 | 201, empty body |
| GET /books/:bookId/ratings/average | Book ID in the URL; public read | 200, JSON number; null for an unrated existing book |
| POST /books/:bookId/comments | Profile Basic authentication and JSON with userId and nonempty comment text | 201, empty body |
| GET /books/:bookId/comments | Book ID in the URL; public read | 200, JSON array, oldest first; [] when empty |

Both POST operations use the existing Geek Text profile username and password.
The required JSON userId must match the authenticated account's ID. The route
writes the ID obtained from authentication. A missing or invalid login returns
401 with a Basic authentication challenge. Valid credentials with a different
userId return 403, and no feedback record is written.

Both POST operations require existing Book and User IDs. The API trims IDs and
comment text. Missing or invalid fields produce 400; nonexistent referenced
records produce 404. A URL with a missing book path segment does not match the
route. Unexpected database failures produce a generic 500 response.
Record IDs and createdAt timestamps are generated by Prisma and the database.
Supplied client IDs and timestamps are ignored. Comment responses contain only
comment fields.

Each accepted rating POST appends a record, including repeat submissions by the
same user for the same book. Confirm the final repeat-rating policy with the
Product Owner. An existing book with no ratings returns null; a nonexistent
book returns 404.

## Files

- src/auth/basic.js verifies the profile password and supplies the authenticated account.
- src/ratings/routes.js checks the author ID, validates the request, and sends the response.
- src/ratings/repository.js checks references and uses Prisma CRUD and aggregation.
- src/ratings/store.js is an isolated in-memory test double.
- prisma/schema.prisma defines Rating, Comment, and their Book/User relations.
- prisma/migrations/20261026221500_add_ratings_comments/migration.sql adds the
  Rating and Comment tables, indexes, constraints, and RLS settings.
- scripts/apply-ratings-comments-db.js checks migration history before deploying
  the ratings and comments migration.

The API uses the shared profile repository for account lookup. Basic
authentication is handled by Express using the existing password hashes.
Supabase provides PostgreSQL storage. The migration enables RLS and revokes
direct anon/authenticated grants for the two feedback tables.

## Local setup

1. Use the team's existing local database configuration and run npm ci.
2. If the ratings and comments migration has not been applied to the development
   database, review it with the team and run npm run ratings:db. The preflight
   stops on unrelated pending migrations, failed migrations, or unexpected
   feature tables. This authentication change needs no new migration.
3. Run npm test. Then start the API with npm start (npm.cmd on Windows).

## Local acceptance demonstration

Keep the API running in one terminal. In a second PowerShell terminal, enter an
existing Geek Text test profile's username and password at the credential prompt.
Use an existing Book.id for the selected book. The profile endpoint supplies the
matching userId. Use HTTPS when testing a hosted API with Basic authentication.

```powershell
$api = 'http://127.0.0.1:3000'
$bookId = 'cmuufyxeb0001uebcajthylz0'
$bookUrl = "$api/books/$bookId"
$credential = Get-Credential -Message 'Enter your Geek Text test profile login'
$login = $credential.UserName + ':' + $credential.GetNetworkCredential().Password
$encoded = [Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes($login))
$headers = @{ Authorization = "Basic $encoded" }
$username = [Uri]::EscapeDataString($credential.UserName)
$userId = (Invoke-RestMethod -Uri "$api/users/$username" -Headers $headers).id
Remove-Variable login, encoded, credential

$rating = @{ userId = $userId; rating = 5 } | ConvertTo-Json
(Invoke-WebRequest -UseBasicParsing -Method Post -Uri "$bookUrl/ratings" -Headers $headers -ContentType 'application/json' -Body $rating).StatusCode
Invoke-RestMethod -Uri "$bookUrl/ratings/average"

$comment = @{ userId = $userId; comment = 'Helpful examples.' } | ConvertTo-Json
(Invoke-WebRequest -UseBasicParsing -Method Post -Uri "$bookUrl/comments" -Headers $headers -ContentType 'application/json' -Body $comment).StatusCode
(Invoke-WebRequest -UseBasicParsing -Uri "$bookUrl/comments").Content
```

Both POST responses should be 201. The average includes the new rating and any
previous ratings for the book. The comments response includes the saved text
and a server timestamp. Restart the API and repeat only the two GET requests
to check that feedback remains available.

## Verification and remaining integration

The automated tests exercise the HTTP routes with isolated data repositories and
test password hashes. They do not connect to shared Supabase. Keep the database
password and test account credentials out of source files.

Purchased-book eligibility and the final repeat-rating policy remain separate
team decisions. Account authentication establishes the author of a submission.
Purchase verification requires a source of completed purchase records.
